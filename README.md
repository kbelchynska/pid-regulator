# Програмний PID-регулятор на STM32F401 (Black Pill + FreeRTOS)

**Мініпроєкт:** налаштування системи керування на макетній платі.

PID-регулятор тримає задану напругу на виході RC-кола: ШІМ → RC-коло → АЦП → PID → ШІМ.
**Уставку задає енкодер**, і той самий енкодер показує напрямок мотором і світлодіодами.

| Дія | Що відбувається |
|---|---|
| Крутимо енкодер **за годинниковою** | уставка **+100 мВ** за клацання, горить **червоний**, мотор крутиться за годинниковою |
| Крутимо **проти** | уставка **−100 мВ** за клацання, горить **синій**, мотор крутиться проти |
| Перестали крутити | через 0,6 с мотор зупиняється; PID і далі тримає напругу |
| **Кнопка** енкодера | мотор стоп, уставка 0 В |
| LED **на платі** (PC13) | **швидко** блимає: PID іде до уставки; **повільно**: вийшов на уставку і тримає |

**Що вже перевірено:**
- PID пройшов 7 тестів на моделі **саме вашого RC-кола з 51 мкФ**;
- автомат станів мотора пройшов 8 тестів, включно зі 100 000 випадкових подій;
- тести ловлять навмисно внесені помилки: вимкнений anti-windup, D по похибці, реверс без паузи;
- уся прошивка зібрана `arm-none-eabi-gcc` з HAL і FreeRTOS від ST без жодного попередження;
- займає **18 КБ Flash / 9 КБ RAM**.

На реальній платі не запускалась — розділ 9 на випадок, якщо щось піде не так.

## 2. Підключення

### RC-коло (об'єкт керування PID)

```
PA6 ──[10 кОм]──●──[100 кОм]──●────► PA1
                │              │
            [51 мкФ]        [1 мкФ]
            + до вузла         │
                │              │
GND ────────────●──────────────●
```

У електроліта 51 мкФ довга ніжка йде до вузла між резисторами, смуга «−» до GND.

### Усе інше (як ви вже зібрали)

| Пін Black Pill | Куди |
|---|---|
| **PA6** | 10 кОм, початок RC-кола (ШІМ) |
| **PA1** | кінець RC-кола, між 100 кОм і 1 мкФ (АЦП) |
| PB6 / PB7 | енкодер CLK / DT |
| PB8 | енкодер SW |
| 3V3 | + енкодера |
| PB12 | → 150 Ом → червоний LED → GND |
| PB13 | → 47 Ом → синій LED → GND |
| PB14 | IN реле 1 (мотор за годинниковою) |
| PB15 | IN реле 2 (мотор проти) |
| G | GND MB102 (спільна земля!) |

Реле: VCC → +5 В, GND → GND, NO → +5 В, NC → GND, COM1/COM2 → два дроти мотора.

## 4. Архітектура

```
                              ┌──► app_motor_ctrl ──► app_motor_fsm ──► Motor_t ◄── drv_motor_relay ► drv_relay
  app_input ──► ШИНА ПОДІЙ ───┤        │ «стан мотора»
  (енкодер,    (Observer)     │        ▼
   кнопка)                    │   app_indicator ──► drv_led
                              │        ▲ «PID на уставці»
                              └──► app_regulator ──► alg_pid
                                       │     ▲
                                   drv_pwm  drv_adc
                                       ▼     │
                                     [ RC-коло ]
```

Шлях одного клацання енкодера за годинниковою:
1. TIM4 апаратно порахував 4 імпульси. Задача вводу побачила 1 клацання і опублікувала на шину подію «+1».
2. Шина роздала подію **двом** підписникам одночасно:
   - **мотору:** подія лягла в його чергу, автомат вирішив «їду CW», реле 1 увімкнулось, стан «RUN_CW» пішов на шину, і індикатор увімкнув червоний;
   - **регулятору:** подія лягла в його чергу, на наступному такті уставка стала на 100 мВ більшою, PID збільшив ШІМ, і напруга на PA1 піднялась.
3. Поки напруга йде до нової уставки, LED на платі блимає швидко. Коли вийшла, повільно.

## 5. PID-регулятор: що робить і як налаштований

**Мета:** тримати на виході RC-кола (PA1) напругу, рівну уставці, попри зміни уставки та збурення.

**Об'єкт:** RC-коло другого порядку (10 кОм / 51 мкФ, потім 100 кОм / 1 мкФ). Сталі часу 0,51 с і 0,1 с, другий ступінь навантажує перший.

**Регулятор** (`alg_pid.c`, такт 10 мс):

```
u = Kp·e + Ki·∫e dt − Kd·d(y_ф)/dt,        e = уставка − вимір,  u = ШІМ 0…100 %
```

| Особливість | Навіщо |
|---|---|
| D по **вимірюванню**, а не по похибці | коли енкодером різко змінюють уставку, ШІМ не стрибає (перевірено тестом) |
| ФНЧ на D (τ = 20 мс) | D не підсилює шум АЦП |
| **Anti-windup** | поки ШІМ у насиченні (100 %), інтегратор не «накачується». Після цього вихід не перелітає уставку (без anti-windup навіть звичайний крок 0 → 1,5 В дає 14 % викиду — перевірено) |
| I зберігає Ki·∫e | зміна Ki на льоту без стрибка ШІМ |
| Рівний період через `vTaskDelayUntil` | PID розрахований на фіксований Ts = 10 мс |

### Результати моделювання вашого макета

| Kp | Ki | Kd | Перерегулювання | Вихід на уставку ±2 % | Що видно |
|---|---|---|---|---|---|
| 0,5 | 0 | 0 | — | не виходить | 0,93 В замість 1,5: велика статична похибка П-регулятора |
| 2 | 0 | 0 | — | не виходить | 1,30 В: більший Kp — менша похибка, але не нуль |
| 2 | 1 | 0 | 0 % | 4,6 с | I прибирає похибку, але повільно |
| 1 | 6 | 0,03 | 15 % | 1,35 с | забагато Ki відносно Kp — викид |
| **2** | **3** | **0,2** | **0,3–0,5 %** | **0,73 с** | **обрано (у `app_config.h`)** |

Ті самі коефіцієнти перевірені при C1 = 41, 61 і 10 мкФ: викид < 1 %, вихід на уставку < 0,8 с.

### Методика налаштування (для звіту)

Метод Циглера–Ніколса на межі стійкості тут **не спрацює**: RC-коло без запізнення не входить в автоколивання при жодному Kp (фаза не досягає −180°). Тому налаштування ручне:

1. `Ki = 0, Kd = 0`, збільшуємо Kp. Бачимо швидшу реакцію, але статична похибка лишається.
2. Додаємо Ki, поки похибка не зникатиме за прийнятний час. Забагато Ki дає викид і коливання.
3. Додаємо Kd, щоб погасити викид. Забагато Kd дає «шум» у ШІМ.

## 6. Налаштування «на живо» і графіки без UART

### Спосіб 1: STM32CubeIDE, Live Expressions (найпростіше)

1. **Run → Debug** (жук), програма запуститься.
2. Праворуч вкладка **Live Expressions** (якщо немає: Window → Show View → Live Expressions).
3. Додайте вирази: `g_reg.setpoint_mv`, `g_reg.measured_mv`, `g_reg.duty_pct`, `g_reg.settled`, `g_reg.exec_us_max`.
4. Крутіть енкодер: значення оновлюються в реальному часі.

**Змінити коефіцієнти:** натисніть паузу, у вкладці **Expressions** змініть `g_pid_tuning.kp` (або ki, kd), продовжіть. Регулятор підхопить нові значення на наступному такті, без перепрошивки.

### Спосіб 2: STM32CubeMonitor (графіки для звіту)

Безкоштовна програма від ST, читає змінні через той самий ST-LINK.
1. Підключіть `.elf` із папки `Debug` проєкту.
2. Виберіть змінні `g_reg.setpoint_mv` і `g_reg.measured_mv`.
3. Отримаєте живий графік перехідного процесу: крок уставки і реакція PID. Це найкраща ілюстрація для звіту.

## 7. Налаштування в STM32CubeIDE (.ioc)

1. **File → New → STM32 Project → MCU/MPU Selector:** STM32F401**CCU6** або **CEU6** (як на чипі). Назва проєкту: `PID_Encoder_Motor`.
2. **System Core → SYS:** Debug = **Serial Wire**, Timebase Source = **TIM11**, System Wake-Up не відмічати.
3. **System Core → RCC:**
   - HSE = **Disable** (внутрішній HSI) або **Crystal/Ceramic Resonator** (кварц 25 МГц);
   - LSE = **Disable**.
4. **Clock Configuration:** PLL Source = HSI (M=16) або HSE (M=25), N=336, P=/4, **System Clock Mux = PLLCLK**, APB1 = /2, APB2 = /1. **HCLK має бути 84 МГц.**
5. **Timers → TIM4:** Combined Channels = **Encoder Mode**, Counter Period = **65535**, Encoder Mode = **TI1 and TI2**, Input Filter обох каналів = **10**. Піни: PB6, PB7.
6. **Timers → TIM3:** Clock Source = **Internal Clock**, Channel1 = **PWM Generation CH1**. Prescaler = **0**, Counter Period = **4199**, auto-reload preload = **Enable**. Пін: **PA6**.
7. **Analog → ADC1:** галка **IN1** (пін **PA1**). Clock Prescaler = **PCLK2 divided by 4**, Resolution = **12 bit**, Continuous Conversion = **Disabled**, Rank 1 → Sampling Time = **84 Cycles**.
8. **Піни GPIO** (клік по піну → режим, потім правий клік → Enter User Label):

| Пін | Режим | Label | GPIO Settings |
|---|---|---|---|
| PB12 | GPIO_Output | LED_RED | Output level Low |
| PB13 | GPIO_Output | LED_BLUE | Output level Low |
| PB14 | GPIO_Output | RELAY_CW | **Open Drain**, Output level **High** |
| PB15 | GPIO_Output | RELAY_CCW | **Open Drain**, Output level **High** |
| PB8 | GPIO_Input | ENC_SW | **Pull-up** |
| PC13 | GPIO_Output | LED_HEART | Output level High (вбудований LED на платі) |

   Для реле з High trigger: PB14/PB15 = Push Pull, Output level **Low**, і `CFG_RELAY_ACTIVE_LOW 0` в `app_config.h`.

9. **Middleware and Software Packs → FREERTOS:** Interface = **CMSIS_V2**.
   - Config parameters: `TOTAL_HEAP_SIZE` = **2048**, `CHECK_FOR_STACK_OVERFLOW` = **Option2**.
   - Tasks and Queues: клацніть по `defaultTask` → **Delete** (якщо не виходить, можна залишити).
10. **Ctrl+S** → Generate Code.

## 8. Як додати код

1. Скопіюйте всі `.h` у `Core/Inc`, а всі `.c` (крім `main_reference.c`) у `Core/Src`.
2. У `Core/Src/main.c` додайте **два рядки** між маркерами:
   ```c
   /* USER CODE BEGIN Includes */
   #include "app.h"
   /* USER CODE END Includes */
   ...
   /* USER CODE BEGIN RTOS_THREADS */
   App_Init();
   /* USER CODE END RTOS_THREADS */
   ```
3. **Project → Build Project**, потім **Run → Run**.

**Перевірка після прошивки:**
1. LED на платі спершу блимає **швидко**: PID виводить напругу на 1,5 В.
2. Приблизно через секунду він блимає **повільно**: напруга тримається.
3. Мультиметром між PA1 і GND має бути **≈ 1,50 В**.

## 9. Якщо щось не так

| Симптом | Що перевірити |
|---|---|
| LED на платі не блимає | `App_Init()` не між маркерами; Timebase не TIM11 |
| LED блимає тільки швидко, PA1 ≈ 0 В | TIM3 не на PA6 або RC-коло підключене не до PA6 |
| LED блимає тільки швидко, PA1 ≈ 3,3 В | PA1 підключено не до кінця RC-кола (між 100 кОм і 1 мкФ); ADC1 не IN1 |
| Напруга «гуляє» навколо уставки | зменште `CFG_PID_KI` або збільште `CFG_PID_KP` |
| Енкодер не міняє ні мотор, ні уставку | TIM4 не в Encoder Mode; енкодер не від 3V3 |
| Червоний горить при повороті проти | `CFG_ENC_INVERT 1` |
| Треба 2 клацання на крок | `CFG_ENC_COUNTS_PER_DETENT 2` |
| Реле працюють навпаки | `CFG_RELAY_ACTIVE_LOW` 1 ↔ 0 + тип піна в CubeMX |
| Плата перезавантажується при старті мотора | електроліти між +5 В і GND; мотор живити від MB102 |

## 10. Патерни проєктування (для звіту)

| Патерн | Де | Навіщо |
|---|---|---|
| **Layered Architecture** | алгоритми, BSP, драйвери, сервіси, застосунок | заміна будь-якого шару не зачіпає інші |
| **Adapter** | `bsp_gpio` | ховає HAL і полярність сигналу |
| **Strategy / Interface** | `drv_motor.h` + `drv_motor_relay.c` | новий драйвер мотора = новий файл, логіка без змін (**Open/Closed**) |
| **State (FSM)** | `app_motor_fsm` | пауза перед реверсом гарантована структурою автомата |
| **Active Object** | `app_regulator`, `app_motor_ctrl` | власна задача + черга. Кожен ресурс має одного власника: **без м'ютексів, без deadlock** |
| **Observer (Pub/Sub)** | `svc_event_bus` | одне клацання енкодера отримують мотор і PID, а ввід про них не знає |
| **Producer–Consumer** | ввід → черги мотора і регулятора | повна черга не блокує ввід |
| **Dependency Injection + Composition Root** | `app.c` | усе «склеювання» в одному файлі |
| **Test Double** | `tests/` | логіка тестується на ПК з фейковим мотором і моделлю RC-кола |

## 12. Тести на комп'ютері

```bash
cd tests
gcc -std=c11 -Wall -Wextra -I../Core/Inc test_pid.c ../Core/Src/alg_pid.c -lm -o tp && ./tp
gcc -std=c11 -Wall -Wextra -I../Core/Inc test_motor_fsm.c ../Core/Src/app_motor_fsm.c -o tf && ./tf
```

**`test_pid`** перевіряє:
- крок 0 → 1,5 В: викид, час, статична похибка;

- anti-windup;
- придушення збурення;

- реверс лише через паузу;
- тайм-аут;
- кнопку стоп;
- 100 000 випадкових подій.
